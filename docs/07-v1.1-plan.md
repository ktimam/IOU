# IOU v1.1 — Plan

> Status: planning.
> v1 is shipped on `main` (commit `b16785d`); 50/50 smoke + 8/8 unit + clean build.
> v1.1 layers real-vetkd, production deployment, and a small set of UX
> hardening items.

## Goals (in priority order)

1. **Real `vetkd_derive_key`** — replace the dev ECDH wrap with the
   IC's BLS12-381 G2 vetkd primitive. The canister calls
   `ic_vetkd_key_derivation::vetkd_public_key` /
   `derive_encrypted_key` to produce a per-canister-derivation-key
   encrypted to the caller's transport key. The PWA holds the
   transport secret in IndexedDB (or in the II-delegated session
   via WebAuthn). No more localStorage keypair.
2. **Production deployment** — `pnpm deploy:ic` builds, deploys to
   `ic` mainnet, wires the cycles wallet, and prints the live URL.
3. **Recovery key** — at first sign-in, the PWA generates a 24-word
   BIP-39 mnemonic that derives the user's transport key. The user
   must save it; if they lose II access, the mnemonic recovers the
   transport key (and therefore access to all current sheet keys).
4. **Replace member** — both members of a pair must sign a
   "replace_member" request to add a new partner (the old member
   leaves). This is the same flow as adding a new pair but with a
   "transfer" semantic. Closing balances of the current sheet
   remain visible to both old + new members.
5. **Google Sheets export** — "Export" button on the SheetPage
   creates a CSV of decrypted entries; the user pastes it into
   Sheets. (v1.1 keeps this manual — OAuth integration is v2.)
6. **Mobile (Capacitor)** — wrap the PWA in a Capacitor shell, add
   the secure-element plugin so the transport key can be stored in
   the device keystore. Single TS codebase, no React Native.

## Out of scope (v2+)

- Multi-pair per user (v1: one pair per user)
- Multi-currency settlement suggestions
- Native Apple/Android push notifications
- Inline OCR for receipts (the user already agreed: in v2)
- Real `vetkd` audit logs

## Phase breakdown

### v1.1.0 — Real vetkd (the hard one)

The current dev wrap (P-256 ECDH + HKDF + AES-GCM) becomes a
fallback. We add a `prodVetkd.ts` adapter that:

1. Generates a BLS12-381 G2 transport key pair (one per user, kept
   in IndexedDB or the platform secure element).
2. Calls a new canister endpoint `vetkd_wrap_sheet_key(sheet_id,
   K_sheet, transport_pub) -> EncryptedKey` which internally:
   - Calls `ic_vetkd_key_derivation::derive_encrypted_key(...)`
     with the `vetkd_test_key` derivation context.
   - Returns the encrypted blob to the PWA.
3. The PWA decrypts the blob using the BLS transport secret + HKDF
   to get the same K_sheet.
4. `unwrapSheetKey` becomes symmetric — given the encrypted blob
   and the transport secret, you get K_sheet.

Feature flag: `VITE_IOU_PROD_VETKD=1` selects the prod path. v1.1
keeps the dev path on by default for local dev (so we don't need
the IC's `vetkd_test_key` enabled in local replica).

### v1.1.1 — Recovery key

- `src/features/recovery/` — BIP-39 mnemonic (24 words,
  256-bit entropy) shown at first sign-in.
- `getTransportKey(mnemonic) -> BLS12-381 G2 secret` deterministic.
- `saveTransportKey(secret)` persists in IndexedDB.
- "Export recovery key" button on the Settings page.
- "Restore from recovery key" flow on `/sign-in` -> "Use recovery
  key" tab.

### v1.1.2 — Replace member

- Canister: `replace_member(req: ReplaceMemberReq) -> Sheet` —
  requires a second signature (the existing member who's staying).
  Implementation: an out-of-band message signed by the existing
  member that includes the sheet id, the old member, and the new
  member; the canister verifies both signatures (the caller's
  sig from the IC, and the offline signature verified by the
  caller submitting it).
- PWA: `/pair/:id/replace` — pick a new member, the old member
  signs a one-shot message, the new member submits it with their
  II auth.

### v1.1.3 — Google Sheets export

- "Export to CSV" button on SheetPage.
- Generates a CSV: date, kind, currency, amount, direction, note,
  convert-from, convert-rate.
- Downloads via `URL.createObjectURL`. The user pastes the CSV
  into a new Google Sheet.

### v1.1.4 — Mobile (Capacitor)

- `npx cap add ios` / `npx cap add android` — wraps the built PWA
  in a native shell.
- Capacitor secure-storage plugin for the transport secret.
- The PWA's existing `/sign-in` II flow still works (II is
  WebAuthn-based, native support in modern iOS/Android WebViews).
- App store metadata, signing, etc. (deferred until vetkd +
  recovery are stable on web).

## Risk register

| Risk | Impact | Mitigation |
| --- | --- | --- |
| `vetkd_test_key` not enabled on local replica | Can't develop prod path locally | Feature flag defaults to dev path; prod CI builds against `ic` mainnet |
| BLS12-381 G2 in WebCrypto | Not yet available cross-browser; requires `noble-curves` or `@noble/bls12-381` polyfill | Bundle `@noble/bls12-381` (~30KB gzipped) for v1.1.0; drop when browsers catch up |
| Recovery-key flow on browser-only | Mnemonic is the only fallback if II fails | Strong "save your recovery key" UX; do not let the user skip the warning |
| Mobile signing requires App Store review | We can't ship mobile the same day as web | v1.1.4 is a separate release; web stays available via the PWA URL |
| Replace-member offline signature UX | The user has to copy/paste a base64 blob | QR-code handoff as v1.1.5 enhancement |

## Open questions for the user

1. Do you want BIP-39 recovery from the start, or in a follow-up?
2. For replace-member, is the offline-signature + QR handoff model
   acceptable, or should we require both members to be online
   simultaneously (e.g. via a canister-mediated session)?
3. Mobile: iOS first, Android first, or both in v1.1.4?
